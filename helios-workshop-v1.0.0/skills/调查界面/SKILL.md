# 调查界面（Investigation Interface）

本技能定义《赫利俄斯之链》调查界面的整体架构、组件规范与视觉风格。
界面为单页 Web 应用，玩家以调查员身份在空间站各区域之间切换，与机器人代理对话、
收集线索、审阅站点日志，并最终提交调查报告。

---

## 1. 整体 UI 架构

### 1.1 单页应用结构

采用单页应用（SPA）架构，所有界面在同一 HTML 文档内通过视图切换实现，
避免页面刷新导致的沉浸感断裂。

核心视图列表：

| 视图 ID         | 名称         | 默认可见 | 解锁条件          |
|-----------------|--------------|----------|-------------------|
| `v-terminal`    | 对话终端     | 是       | 无                |
| `v-evidence`    | 证据板       | 否       | 获得首条线索后    |
| `v-logs`        | 站点日志     | 是       | 无（只读）        |
| `v-report`      | 报告提交     | 否       | 阶段三（Phase 3） |
| `v-ethics`      | 伦理推演线程 | 否       | 阶段二（Phase 2） |

视图切换规则：
- 使用顶部导航栏按钮切换主视图
- 对话终端为默认视图，任何时候可通过快捷键 `Ctrl+1` 回到
- 视图切换采用 CRT 闪烁过渡动画（约 200ms），模拟旧式终端切屏感
- URL hash 同步视图状态（如 `#evidence`），支持浏览器前进/后退

### 1.2 全局状态管理

使用轻量级状态管理（原生 JS Proxy 或 Zustand）维护以下全局状态：

```
GameState {
  currentPhase: 1 | 2 | 3         // 当前阶段
  countdown: number                // 剩余秒数（48小时 = 172800秒，可压缩）
  currentLocation: string          // 当前位置 ID
  conversations: Map<agentId, Message[]>
  evidence: ClueNode[]
  logEntries: LogEntry[]
  unexploredFollowUps: FollowUpNode[]
  reportDraft: string
  ethicsThreads: EthicsThread[]    // 阶段2+可见
}
```

状态变更触发 UI 响应式更新。倒计时使用 `requestAnimationFrame` 驱动，
确保精度并避免 `setInterval` 漂移问题。

## 2. 布局设计

### 2.1 总体布局（ASCII 概览）

```
+================================================================+
| [LOGO] 赫利俄斯之链  | 阶段: 1/3 | [证据板] [日志] [报告]     |  <- 顶栏
+================================================================+
|          |                                                      |
| 侧边栏   |              主视图区域                               |
|          |                                                      |
| [倒计时] |     （对话终端 / 证据板 / 日志 / 报告）              |
|          |                                                      |
| [位置导航]|                                                      |
|  >气闸室 |                                                      |
|  >医疗舱 |                                                      |
|  >机器人 |                                                      |
|   终端   |                                                      |
|  >副工程 |                                                      |
|   师舱   |                                                      |
|          |                                      [未探索跟进节点] |
+----------+--------------------------------------+---------------+
```

### 2.2 顶栏（Top Bar）

高度固定 48px，包含：
- **左侧**：游戏 Logo（简化的赫利俄斯太阳符号）+ 游戏名称
- **中央**：阶段指示器，以分段进度条显示三个阶段的推进状态
  - 阶段一（调查）→ 阶段二（推理）→ 阶段三（裁决）
  - 当前阶段高亮，已完成阶段以绿色填充，未到阶段灰色轮廓
- **右侧**：视图切换按钮组——证据板、站点日志、报告提交
  - 伦理推演按钮在阶段2前显示为锁定图标，hover 时提示"阶段二解锁"

### 2.3 侧边栏（Sidebar）

宽度 220px，可折叠至图标模式（48px），包含：

**倒计时器区域**（上部）：
- 数字显示：`HH:MM:SS` 格式
- 视觉紧迫度分级（详见第5节）
- 阶段名称标注（如"调查阶段 — 剩余 31:22:07"）

**位置导航区域**（下部）：
- 四个可点击位置节点，垂直排列：
  1. 气闸室（Airlock）— 游戏起始位置
  2. 医疗舱（Medical Bay）— 医疗机器人终端
  3. 机器人终端区（Robot Terminals）— 主要对话区域
  4. 副工程师舱（Sub-Engineer Quarters）— 工程机器人区域
- 当前位置以高亮边框 + 发光效果标识
- 位置切换时主视图播放"走廊移动"过渡动画（约 400ms）
- 未解锁位置显示锁定图标（部分位置在特定阶段才可进入）

### 2.4 主视图区域

占据剩余空间（`flex: 1`），根据当前激活视图渲染不同内容组件。
所有视图共享同一容器，通过 CSS `display` 或框架条件渲染切换。

### 2.5 右下角：未探索跟进节点图

固定定位在主视图右下角（`position: fixed; bottom: 16px; right: 16px`）：
- 小型圆形节点图，显示尚未深入探索的线索分支
- 节点为灰色圆点，数量随调查深入减少
- hover 展开显示跟进提示文本
- 点击可直接跳转至对应的对话终端或证据板节点
- 当所有跟进都被探索后，节点图消失并显示"全线索已覆盖"提示

## 3. 对话终端设计

### 3.1 界面结构

对话终端是玩家与机器人代理交互的主要界面，采用聊天式布局：

```
+------------------------------------------------------+
| [代理头像]  代理名称: HELIOS-7                         |
|              状态: 在线 | 信任度: ████████░░ 72%      |
+------------------------------------------------------+
|                                                      |
|  [代理] 欢迎，调查员。我的日志对你是开放的。           |
|           有什么需要了解的？                           |
|                                                      |
|           [时间戳: 03:22:15]                          |
|                                                      |
|  [你]    请调出事故当晚的传感器记录。                  |
|                                                      |
|           [时间戳: 03:22:41]                          |
|                                                      |
|  [代理] 正在检索... ████░░░░░░                        |
|                                                      |
+------------------------------------------------------+
| [输入你的问题...]                          [发送 ▶]   |
+------------------------------------------------------+
```

### 3.2 代理标签页

当玩家需要与多个机器人代理对话时：
- 顶部显示代理标签页（Tab），每个标签包含：
  - 代理图标（简化的机器人轮廓 + 颜色标识）
  - 代理名称缩写
  - 未读消息指示器（红色小圆点）
  - 在线/离线状态（绿色/红色小点）
- 标签页可左右滑动（当代理数量超过可视区域时）
- 切换标签页时保留各代理的独立对话历史

### 3.3 消息渲染

**代理消息**（左对齐）：
- 代理头像（小型圆形图标）置于消息左侧
- 消息气泡使用半透明深色背景（`rgba(0, 255, 170, 0.08)`）
- 文字颜色为代理主题色（每个代理有独立的颜色标识）
- 系统消息（如"[代理正在执行计算]"）使用斜体、较低透明度

**玩家消息**（右对齐）：
- 无头像，消息气泡背景略浅
- 文字颜色为标准的终端绿（`#00FF96`）

**打字指示器**：
- 代理"思考"时显示三个脉动的光点：`● ● ●`
- 光点以代理主题色显示，依次亮起，周期 1.2 秒
- 思考时间超过 3 秒时显示文字提示："正在检索数据..."或"正在分析..."

### 3.4 输入框设计

- 单行输入框，支持 `Enter` 发送、`Shift+Enter` 换行
- 输入框左侧显示 `>` 提示符（终端风格）
- 发送按钮为三角形箭头图标 `▶`
- 输入框为空时发送按钮置灰
- 历史记录：使用上下箭头键浏览之前发送过的消息（最多保存 20 条）

### 3.5 消息历史管理

- 每个代理的对话历史独立存储
- 对话区域自动滚动至最新消息
- 当有新消息到达且用户已向上滚动时，显示"新消息 ↓"浮动按钮
- 对话历史可在代理标签页中通过搜索图标过滤关键词

## 4. 证据板设计

### 4.1 节点图可视化

证据板采用力导向图（Force-Directed Graph）布局，使用 D3.js 或轻量替代方案：

```
+------------------------------------------------------+
| 证据板                          [筛选] [搜索] [缩放]  |
+------------------------------------------------------+
|                                                      |
|        [通讯记录]----[异常信号]                       |
|            |              |                           |
|            |         [时间线矛盾]                     |
|            |              |                           |
|       [HELIOS-7]----[传感器数据]                      |
|            |                                          |
|       [医疗日志]----[药物清单]                        |
|                                [被删除的文件]         |
|                                                      |
|  ● 已确认  ● 争议中  ● 隐藏/未发现                    |
+------------------------------------------------------+
| 选中线索详情面板（可折叠）                             |
| 名称: 通讯记录                                       |
| 描述: 事故前12分钟的加密通讯片段...                    |
| 关联: 异常信号, HELIOS-7                              |
| 可信度: 高                                           |
| 来源: 机器人终端查询                                  |
+------------------------------------------------------+
```

### 4.2 节点样式规范

| 状态     | 颜色       | 边框     | 背景           | 说明               |
|----------|------------|----------|----------------|--------------------|
| 已确认   | `#00FF96`  | 实线     | 半透明绿色     | 经多方验证的线索   |
| 争议中   | `#FFB800`  | 虚线     | 半透明黄色     | 来源矛盾/未确认    |
| 隐藏     | `#666666`  | 点线     | 深灰           | 尚未发现的线索     |
| 选中     | `#00BFFF`  | 粗实线   | 半透明蓝色     | 当前查看的线索     |

### 4.3 交互行为

- **拖拽**：节点可拖拽重新布局，松手后力导向算法重新计算
- **缩放**：鼠标滚轮缩放，双指缩放（触屏），缩放范围 0.3x ~ 3x
- **点击节点**：底部展开详情面板，显示线索描述、来源、关联关系、可信度
- **双击节点**：以该节点为中心重新布局图
- **右键菜单**：标记为"已确认"/"争议中"、添加自定义备注
- **连接线**：鼠标悬停连线时显示关系描述（如"时间线矛盾""因果关系"）

### 4.4 证据板统计

顶部状态栏显示：
- 已收集线索数 / 总线索数
- 已确认数 / 争议数 / 隐藏数
- 关联密度指标（高关联度线索以更大节点显示）

## 5. 倒计时器机制

### 5.1 时间压缩比

游戏内 48 小时映射为实际游戏时长（可配置），默认压缩比：
- 1 游戏小时 = 2 实际分钟
- 48 游戏小时 = 96 实际分钟（约 1.5 小时完成游戏）
- 可在游戏设置中调整压缩比

### 5.2 视觉紧迫度分级

| 剩余时间（游戏时间） | 颜色          | 效果                           |
|----------------------|---------------|--------------------------------|
| > 24 小时           | `#00FF96` 绿色 | 正常显示，无特殊效果           |
| 12-24 小时          | `#FFB800` 黄色 | 数字微微闪烁（每5秒闪一次）    |
| 6-12 小时           | `#FF6B00` 橙色 | 持续脉动效果，边框发光         |
| 2-6 小时            | `#FF0044` 红色 | 快速脉动，倒计时数字放大       |
| < 2 小时            | `#FF0044` 红色 | 全屏边缘红色脉冲警告           |

### 5.3 阶段过渡动画

阶段切换时播放以下动画序列（总时长约 1.5 秒）：
1. 倒计时数字冻结，颜色变为白色（200ms）
2. 屏幕中央出现阶段过渡标题："阶段一：调查 → 阶段二：推理"（300ms 淡入）
3. 背景轻微暗化（vignette 效果加深）（200ms）
4. 过渡标题淡出，新阶段名称闪现（300ms）
5. 倒计时颜色根据新阶段重置（200ms 淡入）
6. 解锁的新功能按钮依次亮起（300ms 依次出现）

### 6.3 交互功能

- **搜索**：全文搜索，匹配关键词高亮显示

- **锁定条目**：显示为乱码或加密符号，hover 提示所需权限等级
- **展开条目**：点击日志行展开完整内容（长条目默认折叠）
- **导出线索**：部分日志条目可"提取为线索"，直接添加到证据板
- **时间线视图**：切换为时间线模式，以可视化方式展示日志时间分布

## 7. 报告提交界面（阶段三）

### 7.1 解锁条件

当游戏进入阶段三（裁决阶段）时，报告提交界面在顶栏中亮起。
玩家必须在此阶段结束前提交最终报告。

### 7.2 界面结构

```
+------------------------------------------------------+
| 调查报告                                  [自动保存 ✓]|
+------------------------------------------------------+
|                                                      |
| 引导提示（可折叠）:                                   |
|  ▸ 你认为事故的直接原因是什么？                       |
|  ▸ 哪些代理的行为存在异常？                           |
|  ▸ 你的结论基于哪些关键证据？                         |
|  ▸ 伦理层面，你如何评价各代理的决策？                 |
|                                                      |
| +--------------------------------------------------+ |
| |                                                  | |
| |  自由文本编辑区域                                | |
| |  （支持多段落，无字数限制）                      | |
| |                                                  | |
| |                                                  | |
| +--------------------------------------------------+ |
|                                                      |
| 字数统计: 0 字 | 关联线索: 点击添加引用               |
|                                                      |
|                    [提交报告 ▶]                       |
+------------------------------------------------------+
```

### 7.3 编辑器功能

- **自由文本编辑器**：纯文本输入，终端风格（等宽字体，深色背景）
- **引导提示**：可折叠的问题列表，帮助玩家组织思路
  - 点击问题可将问题文本插入编辑器作为段落标题
- **线索引用**：从证据板中拖拽线索节点到编辑器，自动插入引用标记
- **自动保存**：每 30 秒自动保存草稿，显示保存状态指示器
- **字数统计**：实时显示已输入字数

### 7.4 提交动画

点击"提交报告"按钮后播放以下动画序列：
1. 按钮文字变为"正在加密传输..."，按钮宽度扩展（300ms）
2. 屏幕出现终端打字效果："ENCRYPTING REPORT..."（500ms）
3. 进度条从 0% 到 100%（800ms）
4. 屏幕短暂闪白，然后暗化（200ms）
5. 中央显示大号文字："报告已提交 — 调查结束"（淡入 400ms）
6. 自动跳转至结算/评分界面

## 8. 技术栈推荐

### 8.1 推荐方案：单文件 HTML/CSS/JS

对于原型开发和快速迭代，推荐使用单文件方案：
- **HTML5**：语义化结构
- **CSS3**：CSS 变量定义设计令牌，CSS Grid/Flexbox 布局
- **Vanilla JS**：无框架依赖，使用 ES Module 组织代码

优势：零构建步骤，可直接浏览器打开，方便分享与测试。

### 8.2 进阶方案：轻量框架

如需更复杂的状态管理：
- **Vue 3 + 单文件组件**：响应式状态管理，模板语法简洁
- **React + Zustand**：如团队更熟悉 React 生态
- **Svelte**：编译时框架，产物极小，适合游戏场景

### 8.3 可视化库

- **证据板节点图**：D3.js（力导向图）或 Cytoscape.js（专为图数据设计）
- **动画**：GSAP（GreenSock）或纯 CSS 动画
- **打字效果**：自定义 JS 或使用 Typed.js

### 8.4 字体选择

- 主字体：`JetBrains Mono` 或 `Fira Code`（等宽，支持连字）
- 中文回退：`Noto Sans Mono CJK SC`
- 标题字体：`Orbitron`（科幻风格标题字体，仅用于 Logo 和阶段标题）

## 9. 视觉风格指南

### 9.1 核心美学

整体风格为"科幻终端"（Sci-Fi Terminal），灵感来源于：
- 复古 CRT 显示器效果（扫描线、轻微闪烁）
- 现代科幻电影中的全息界面（如《银翼杀手2049》《火星救援》）
- 军事/航天控制中心的操作界面

### 9.2 色彩方案

| 用途           | 色值          | 说明                       |
|----------------|---------------|----------------------------|
| 背景（最深）   | `#0A0E14`     | 主背景色                   |

### 9.3 视觉特效

- **扫描线**：全局叠加层，水平线条间距 2px，透明度 3%
- **CRT 弯曲**：极微弱的 `barrel` 变形（可选，通过 CSS `filter` 实现）
- **发光效果**：重要文字/按钮使用 `text-shadow` 或 `box-shadow` 产生柔和辉光
- **打字光标**：输入框末尾显示闪烁的方块光标 `█`
- **噪点纹理**：极低透明度的噪点叠加层（可选），增强模拟感

### 9.4 排版规范

- 基础字号：14px（正文）
- 标题字号：18px（面板标题）、24px（视图标题）、32px（阶段标题）
- 行高：1.6（正文）、1.2（标题）
- 字间距：正文 0.5px、标题 2px
- 段落间距：16px

### 9.5 音效提示（可选增强）

- 新消息到达：短促的电子"哔"声
- 阶段过渡：低沉的引擎嗡鸣过渡音
- 倒计时警告：每秒一次的心跳声
- 线索发现：清脆的"叮"声
- 报告提交：数据传输的数字音效
