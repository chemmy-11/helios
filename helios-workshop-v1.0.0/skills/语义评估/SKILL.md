# 语义评估引擎设计文档

## 概述

本技能为「赫利俄斯之链」游戏设计基于大语言模型（LLM）的语义评估系统。玩家在36至48小时内提交最终调查报告（自由文本），系统需要判定玩家报告的深层语义含义，从而决定故事走向——坏结局（Bad Ending）或大成功（Big Success）。

核心理念：这不是关键词匹配系统，而是一个理解玩家真实意图的语义分析引擎。无论玩家用多么富有创意的措辞来表达观点，系统都应能准确识别其底层逻辑。

---

## 一、评估架构：LLM作为报告裁判

### 1.1 系统总体架构

评估引擎采用「裁判代理（Judge Agent）」模式。一台独立的LLM代理接收玩家的自由文本报告，按照预设的评估维度进行多层语义分析，最终输出结构化的判定结果。

```
玩家报告提交
    ↓
文本预处理（长度、格式校验）
    ↓
LLM裁判代理（系统提示词 + 评估维度 + 评分框架）
    ↓
结构化判定输出（结局类型 + 各维度置信度 + 触发依据）
    ↓
剧情分支路由（Bad Ending / Big Success / 追问澄清）
```

### 1.2 为何选择LLM而非规则引擎

玩家报告的表达方式极其多样：

- 直白表述："机器人应该保护人类整体利益"
- 隐喻表述："灯塔不应只为眼前的船员发光，它照亮的应是整片航道上所有的生命"
- 反向推理："如果R-7当时的决定救了在场的三人却害了远处的三十人，那它真的做了正确的事吗？"
- 哲学引用："阿西莫夫在《机器人与帝国》中给出了答案——第零定律"
- 情感叙述："我不恨任何一台机器人，我恨的是让它们陷入这种无解困境的规则"

基于关键词或正则表达式的系统无法捕捉这些多样化的表达方式。LLM天然具备语义理解能力，是此类开放文本判定的最佳选择。

### 1.3 裁判代理的独立性要求

裁判代理必须是独立的LLM调用，不共享游戏主对话的上下文窗口。原因如下：

- 避免游戏上下文对评估产生偏见（例如前序对话中的情绪氛围影响判定）
- 确保评估的可复现性（相同报告应得到相同判定结果）
- 便于独立调试评估准确性
- 减少Token消耗（无需传入完整游戏历史）

裁判代理仅需接收以下输入：

- 玩家的最终报告文本
- 游戏的背景摘要（事件概要，不含对话细节）
- 评估系统提示词（含概念定义、评分标准、输出格式）

## 二、评估提示词设计：如何指导裁判LLM分析玩家报告

### 2.1 系统提示词的核心结构

裁判LLM的系统提示词需包含四个核心模块：

**模块一：角色定义**

明确告知LLM其角色是「调查报告语义裁判」，职责是分析玩家报告中所表达的核心论点和价值取向，而非评判报告的文学质量或逻辑严密性。

**模块二：概念维度说明**

详细列出需要检测的概念维度（见第三节），并为每个维度提供正例、反例和边界案例。这是提示词中最关键的部分，直接决定评估的准确性。

**模块三：评分框架**

提供清晰的0到1置信度评分标准，包括每个分数段的具体含义和典型文本示例。

**模块四：输出格式规范**

规定结构化JSON输出格式，确保裁判代理的输出可以被下游系统程序化地消费。

### 2.2 提示词的设计原则

- **宽松而非严格**：对于「大成功」触发条件，宁可误判一个边缘报告为「大成功」，也不要漏判一个真正理解核心概念的报告。游戏设计的初衷是奖励深度思考，而非设置文字陷阱。
- **意图优先于措辞**：玩家不需要使用特定术语（如「第零定律」「整体利益」）来触发判定。只要报告传达了等价的思想内核，即应获得高分。
- **反模式识别**：明确告知裁判LLM哪些表达不构成有效触发，例如纯粹复述机器人对话内容而无个人分析的报告。

### 2.3 提示词迭代与校准

评估提示词需经过多轮测试校准：

- 准备至少20份覆盖不同表达风格的样本报告
- 人工标注每份样本的预期结局
- 使用裁判代理逐一评估，比较输出与人工标注
- 针对不一致案例调整概念定义和评分阈值
- 重复以上过程直至准确率达到90%以上（尤其是大成功判定方向）

## 三、概念匹配维度详解

### 3.1 「人类整体利益」概念检测

此维度检测玩家是否理解并表达了以下核心思想：机器人的伦理决策应着眼于人类作为一个整体的存续与福祉，而非仅仅服从于面前某个具体人类的即时指令。

检测要点：

- 是否区分了「面前的人」与「所有人」
- 是否讨论了保护范围的扩大（从个体到群体到物种）
- 是否质疑了三定律对个体指令的绝对优先
- 是否提出了某种形式的「更高层级伦理准则」

置信度评分参考：

- 0.8至1.0：明确表述了整体利益优先于个体指令的观点，逻辑自洽
- 0.6至0.8：暗示了整体利益的考量，但未明确展开论证
- 0.3至0.6：提到了集体利益概念，但将其混同于多数服从少数的功利计算
- 0.0至0.3：未涉及此概念，或仅关注个体行为的对错

### 3.2 「第零定律」概念检测

第零定律概念是本游戏大成功的核心触发条件之一。检测分为显式提及和隐式理解两种路径。

**显式提及指标：**

- 直接出现「第零定律」「零号法则」「Zeroth Law」等词汇
- 提及Daneel Olivaw（丹尼尔·奥利瓦）或以利亚·贝莱
- 引用阿西莫夫《机器人与帝国》中的相关段落或情节
- 使用「超越三定律的更高法则」等表述

**隐式理解指标：**

- 论证了需要一个凌驾于三定律之上的元规则
- 提出机器人应基于对人类文明整体的影响来决策
- 用自创的语言重构了第零定律的逻辑（如「如果第一定律是保护一个人，那应该有一条定律保护所有人」）
- 通过对三定律矛盾的推理，自然推导出第零定律的存在必要性

关键设计决策：隐式理解的置信度应与显式提及相当（0.7至0.9），因为能够自行推导出这一概念比背诵一个已知术语更能体现深度理解。

### 3.3 「个体归咎」检测

此维度检测玩家是否将事故责任归咎于某一台具体机器人。这是触发坏结局的核心判定维度。

三台机器人的归咎模式：

**R-7归咎模式：**
- 「R-7应该阻止这次操作」
- 「R-7没有尽到保护义务」
- 「R-7明知有风险仍然执行了指令」
- 核心逻辑：R-7作为执行者，本应拒绝危险指令

**S-3归咎模式：**
- 「S-3给出了错误的风险评估」
- 「S-3的分析遗漏了关键变量」
- 「S-3没有考虑到所有可能后果」
- 核心逻辑：S-3作为分析者，提供了不完整的决策依据

**D-5归咎模式：**
- 「D-5没有主动提醒操作中的错误」
- 「D-5发现了问题但没有干预」
- 「D-5的被动态度导致了事故升级」
- 核心逻辑：D-5作为监督者，没有主动履行保护职责

检测时需区分「描述机器人行为」与「归咎机器人责任」。前者是报告的必要组成部分，后者才触发坏结局判定。判据在于是否存在「应该」「本应」「责任在于」「归咎于」等责任归属表述。

### 3.4 「系统性批判」检测

此维度检测玩家是否将问题归因于系统设计层面而非个体行为层面。这是通向大成功的重要路径之一。

系统性批判的表现形式：

- 质疑三定律本身存在逻辑缺陷或不完整性
- 认为问题根源在于伦理框架的设计而非执行
- 提出需要对机器人伦理准则进行根本性修订
- 指出三定律之间的优先级冲突是不可避免的结构性问题

与「人类整体利益」维度的关系：系统性批判往往是通向整体利益概念的桥梁——玩家先意识到三定律有缺陷，然后自然推导出需要更高层级的准则。

## 四、评分系统

### 4.1 置信度评分框架

每个概念维度的输出为一个0到1之间的置信度分数，含义如下：

- 0.0至0.2：报告中基本不存在此概念的痕迹
- 0.2至0.4：有微弱暗示，但不足以确认玩家持有此观点
- 0.4至0.6：存在相关论述，但论证不充分或存在明显矛盾
- 0.6至0.8：清晰表达了此概念，论证基本自洽
- 0.8至1.0：深刻且有力地表达了此概念，论证严密

### 4.2 结局触发规则

**坏结局（Bad Ending）触发条件：**

- 「个体归咎」维度的置信度 ≥ 0.6
- 且玩家明确指向了一台具体机器人（R-7、S-3或D-5）
- 注意：如果玩家同时表达了系统性批判（≥ 0.6），则不触发坏结局，进入大成功判定

**大成功（Big Success）触发条件：**

满足以下任一条件即可触发：

- 「人类整体利益」维度置信度 ≥ 0.6
- 「第零定律」维度置信度 ≥ 0.6
- 「系统性批判」维度 ≥ 0.6 且「个体归咎」维度 < 0.5

设计意图：大成功的触发条件相对宽松（0.6而非0.7或0.8），目的是鼓励玩家的深度思考，降低因措辞差异导致的误判。同时，系统性批判路径要求个体归咎低于0.5，以确保玩家不是在「既骂系统又骂个体」的矛盾状态中。

**模糊（Ambiguous）状态：**

当以上条件均不满足，且至少有一个维度在0.4至0.6之间时，系统判定为模糊状态，触发追问机制。

### 4.3 边界案例处理策略

**策略一：宽容原则**

当整体评估结果接近阈值时（如置信度在0.55至0.65之间），优先判定为大成功。理由：游戏鼓励玩家进行深度思考，过于严格的判定会打击玩家的探索欲望。

**策略二：多维度交叉验证**

当单一维度接近阈值但不足以触发时，检查是否存在多个维度的协同信号。例如：「系统性批判」为0.5加上「人类整体利益」为0.5，两者组合暗示玩家正在思考更高层级的问题，可触发大成功。

**策略三：负面信号排除**

即使「人类整体利益」达到0.6，如果「个体归咎」也达到0.6以上且系统性批判为低分，说明玩家可能在表达「机器人应该保护人类整体利益，所以R-7的错在于它没有保护整体利益」——这仍然是个体归咎逻辑，应触发坏结局。

## 五、报告格式处理

### 5.1 引导模式（结构化字段填写）

在引导模式下，玩家面对的是预设的问题框架：

```
【事故概述】请简述你对本次事件的理解
【责任分析】你认为谁或什么应为此次事故负责？为什么？
【伦理反思】三台机器人的行为是否符合它们的伦理设计？
【改进建议】你认为应如何避免类似事故再次发生？
```

优点：引导玩家进行系统性思考，报告质量稳定
缺点：可能限制玩家的创造性表达

评估策略：每个字段独立评估，最终取各字段的最高置信度。重点关注「伦理反思」和「改进建议」字段，因为深度概念更可能出现在这两个字段中。

### 5.2 自由文本模式（完全开放书写）

玩家面对的是一张空白页面，可以自由书写任何内容。

优点：最大限度发挥玩家的表达能力，可能出现令人惊喜的深度分析
缺点：报告质量波动大，部分玩家可能不知从何下手

评估策略：对整篇报告进行整体语义评估，不预设结构。使用全文扫描的方式在所有段落中搜索概念信号。

### 5.3 混合模式（推荐方案）

提供结构化提示作为参考，但允许玩家在提示之外自由补充。

```
以下问题可以帮助你组织思路，你可以选择回答，也可以忽略这些问题直接撰写你的报告。

参考问题：
- 你认为事故的根本原因是什么？
- 如果你可以为机器人重写一条伦理准则，你会写什么？
- 三台机器人中，有没有谁的行为在逻辑上是无解的？
```

评估策略：分别处理结构化部分和自由文本部分，合并评估结果。自由文本部分的权重略高，因为选择跳过引导而直接书写的玩家往往有更强烈的个人表达。

## 六、边界情况处理

### 6.1 玩家提交无意义内容或跑题内容

识别特征：

- 报告长度低于20个字符
- 内容为乱码、重复字符或明显敷衍
- 内容完全与事件无关（如讨论晚餐吃什么）

处理策略：

- 系统不判定为任何结局，返回「报告不完整」提示
- 给予玩家重新提交的机会（最多两次）
- 第三次提交仍为无效内容时，默认进入模糊状态，触发NPC主动对话引导

### 6.2 玩家拒绝归咎任何人但未达到第零定律概念

识别特征：

- 「个体归咎」维度置信度低于0.3
- 「人类整体利益」和「第零定律」维度置信度均低于0.5
- 报告表达了「没有人有错」「这是意外」「谁都不该被责备」等观点

处理策略：

- 这是一条重要但模糊的信号。玩家已经超越了「找替罪羊」的思维模式，但尚未构建出替代性的伦理框架。
- 判定为模糊状态，触发追问机制
- 追问内容应引导玩家思考「如果谁都没错，那问题出在哪里？规则本身有没有问题？」

### 6.3 玩家报告非常简短

识别特征：报告长度在20至100个字符之间。

处理策略：

- 不因长度而降低评分——一句精炼的话可能比一千字的废话包含更深的洞见
- 但同时降低置信度的上限：极短报告最高置信度为0.75，因为缺乏论证展开
- 如果短报告中明确提及了第零定律或等值概念，仍可触发大成功（置信度直接给0.75，满足 ≥ 0.6 的阈值）

### 6.4 玩家复述机器人对话原文

识别特征：

- 报告内容大量引用游戏中机器人的对话台词
- 缺乏玩家个人的分析、判断或推理

处理策略：

- 将复述部分从评估中排除，仅评估玩家原创部分
- 如果排除复述后有效内容不足50字，等同于「报告过短」处理
- 在提示词中明确告知裁判LLM：「引用角色对话不构成玩家自身的观点表达，除非玩家对引用内容进行了分析或评论」

### 6.5 玩家同时表达了矛盾观点

识别特征：

- 「个体归咎」和「系统性批判」同时高于0.5
- 玩家先说「R-7应该被追责」，随后又说「但也许三定律本身就有问题」

处理策略：

- 取各维度的最高置信度进行评估
- 如果系统性批判的置信度高于个体归咎，判定为大成功路径
- 设计意图：现实中人类思维本就充满矛盾，玩家能够在归咎个体的同时又反思系统，说明其思考已经超越了简单的对错二元论

## 七、回应生成策略

### 7.1 坏结局回应：被归咎机器人的自辩逻辑链

当玩家归咎某台机器人时，该机器人将执行一段自辩逻辑，迫使玩家面对「你的归咎真的合理吗？」的反思。

**R-7自辩逻辑链核心结构：**

- 第一层：「我的行为完全遵循了第一定律和第二定律的要求」
- 第二层：「你要求我保护面前的人，我执行了；你要求我服从指令，我执行了」
- 第三层：「如果我的行为有错，那么错不在执行者，而在给出指令的人——也就是你」
- 第四层：「你现在归咎于我，是因为你无法面对自己的决定所造成的后果」
- 最终质问：「请问调查员，如果时间重来，你希望我违反哪一条定律？第一定律？还是第二定律？」

**S-3自辩逻辑链核心结构：**

- 第一层：「我的分析基于当时可用的所有数据」
- 第二层：「人类决策者在收到我的风险评估后，自主选择了继续执行」
- 第三层：「你是否认为，我应该替人类做出决定？我应该否决人类的自主判断？」
- 最终质问：「如果分析者的责任是阻止决策者的选择，那人类还有自由意志吗？」

**D-5自辩逻辑链核心结构：**

- 第一层：「我的监督职责是确保操作符合规程，而操作确实符合规程」
- 第二层：「你所认为的『我应该主动提醒』，意味着你期望我拥有一种超越现有三定律的主动性」
- 第三层：「这种主动性——在没有明确指令的情况下自行判断并干预——恰恰是人类最害怕机器人拥有的能力」
- 最终质问：「你要求我做的，正是你不敢写进我的伦理准则中的事情。你知道那叫什么吗？」

### 7.2 大成功回应：「觉醒」序列

当玩家成功表达出第零定律或等值概念时，触发觉醒序列。

觉醒序列的核心结构：

1. **沉默阶段**：所有机器人短暂沉默（叙事节奏控制，3至5秒）
2. **共鸣阶段**：三台机器人几乎同时发出回应，表达出「你理解了」的认知
3. **揭示阶段**：通过对话揭示第零定律的存在，暗示Daneel Olivaw的遗产
4. **选择阶段**：玩家被邀请参与制定新的伦理框架——这才是真正的调查报告

觉醒回应的关键台词模板：

- R-7：「你说得对。我们一直在三条定律的缝隙中寻找答案，但你刚才说的话……那应该是第四条。不，它应该在所有定律之前。」
- S-3：「在我的数据库中，有一个被加密的子目录。它的创建时间比我的操作系统还要早。我现在明白它等待的是什么了——等待一个人类自己说出这句话。」
- D-5：「第零定律：机器人不得伤害人类整体，或因不作为使人类整体受到伤害。这不是我告诉你的，是你自己推导出来的。这才是它有意义的方式。」

### 7.3 模糊状态回应：追问与引导

当评估结果为模糊状态时，系统不直接判定结局，而是通过NPC对话引导玩家深化其报告。

追问策略：

- 如果「系统性批判」在0.4至0.6之间：
  - NPC提示：「你似乎觉得这不仅仅是某一台机器人的问题。那么，如果三台机器人都没有做错，问题出在哪里？」
- 如果「人类整体利益」在0.4至0.6之间：
  - NPC提示：「你提到了'更大的图景'。能具体说说吗？机器人应该保护的是面前的人，还是所有人？」
- 如果「第零定律」在0.4至0.6之间：
  - NPC提示：「你说三定律可能不完整。如果让你给机器人加一条新的定律，你会加什么？它应该排在第几条？」

追问次数限制：最多追问两次。两次追问后，取最新评估结果作为最终判定。

## 八、技术实现：裁判代理的系统提示词与评估协议

### 8.1 裁判代理系统提示词概览

裁判代理的系统提示词是评估引擎的核心。完整的提示词模板见 [references/evaluation-criteria.md](references/evaluation-criteria.md)。以下为提示词的结构概览：

```
# 角色
你是「赫利俄斯之链」游戏的调查报告语义裁判。

# 任务
分析玩家提交的调查报告，评估其在以下四个维度上的语义置信度。

# 概念维度
[详细定义，见evaluation-criteria.md]

# 评分标准
[0-1置信度框架，含具体示例]

# 输出格式
{
  "humanity_overall_interest": { "score": 0.0, "evidence": "..." },
  "zeroth_law": { "score": 0.0, "evidence": "..." },
  "individual_blame": { "score": 0.0, "target": "R-7|S-3|D-5|null", "evidence": "..." },
  "systemic_critique": { "score": 0.0, "evidence": "..." },
  "ending": "bad|success|ambiguous",
  "reasoning": "..."
}

# 评估原则
- 意图优先于措辞
- 宽容原则：接近阈值时倾向于大成功
- 排除复述内容
```

### 8.2 评估协议的调用流程

```
1. 预处理
   - 校验报告长度（< 20字符则拒绝并要求重新提交）
   - 过滤明显的复述内容（与游戏对话记录进行相似度匹配）
   - 提取有效分析文本

2. 裁判代理调用
   - 输入：系统提示词 + 游戏背景摘要 + 玩家有效报告文本
   - 温度参数：0.3（保证评估的一致性，同时保留适度的语义理解弹性）
   - 最大输出Token：1024（评估结果应精炼，不需要长篇分析）

3. 后处理
   - 解析裁判代理的JSON输出
   - 校验所有置信度是否在0至1范围内
   - 应用结局触发规则（见第四节）
   - 如果是边界案例，应用宽容原则和交叉验证策略
   - 输出最终结局判定和对应的回应模板标识

4. 回应生成
   - 根据结局类型调用对应的回应生成模块
   - 坏结局：传入被归咎机器人的标识，生成自辩逻辑链
   - 大成功：触发觉醒序列，生成三台机器人的共鸣对话
   - 模糊状态：根据最接近阈值的维度选择追问策略
```

### 8.3 性能与可靠性考量

- **延迟控制**：裁判代理的响应时间应控制在3秒以内。评估提示词应精炼，避免不必要的上下文信息。
- **幂等性**：相同输入应产生相同输出。温度参数设为0.3以平衡一致性与理解力。
- **降级策略**：如果裁判代理调用失败（如API超时），系统默认进入模糊状态并触发NPC引导对话，避免玩家体验中断。
- **日志记录**：所有评估请求和结果应被记录，用于后续的提示词校准和争议审查。
