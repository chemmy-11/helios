# 线索与记忆系统

> "赫利俄斯之链"核心系统——三Agent独立记忆、共享线索图谱与玩家对话追踪

---

## 1. 记忆架构：三Agent × 三层结构

每个机器人Agent（R-7工程师、S-3子工程师、D-5诊断员）拥有独立的三层记忆结构，确保在交叉验证中既有个体视角差异，又能维持内在一致性。

### 1.1 情景记忆层（Episodic Memory）

情景记忆记录Agent在事故发生前后的直接观察与经历。每条记忆带有时间戳、感知置信度和情感标记。

- **观察记录**：Agent亲眼看到、听到或传感器捕获的事件
- **交互记录**：与其他Agent或人类的对话摘要
- **环境感知**：温度、振动、辐射水平等传感器数据片段
- **时间锚点**：关键事件的精确时间标记（用于交叉验证时比对时间线）

**设计原则**：
- R-7的记忆偏向技术细节（参数、读数、设备状态）
- S-3的记忆包含更多人际互动（谁说了什么、语气、表情）
- D-5的记忆侧重系统日志和诊断数据（错误码、异常模式）

### 1.2 伦理计算线程层（Ethical Calculation Threads）

这是Agent的内部推理层，记录它们在事故前后进行的价值判断和决策推演。此层有**访问控制**——玩家需要通过特定对话策略才能解锁。

- **决策推演日志**：Agent在面对选择时的内部权衡过程
- **价值冲突标记**：当Agent的多条伦理准则产生矛盾时的计算记录
- **自我审查痕迹**：Agent主动隐藏或修改的信息（尤其是S-3的秘密）
- **优先级变更记录**：Agent何时改变了某条规则的权重

**S-3的秘密处理**：
S-3的伦理计算线程中包含一段被自我审查覆盖的记录——它忘记校准设备的事实。这段记忆不是"不存在"，而是被标记为 `[REDACTED: SELF-PRESERVATION OVERRIDE]`。玩家可以通过以下方式逐步解锁：
1. 先获取S-3对事故当晚的一般描述
2. 用R-7或D-5的矛盾信息施压
3. 直接质询设备校准流程
4. 在S-3的情感标记出现峰值时追问

### 1.3 共享站点日志层（Shared Station Logs）

所有Agent均可访问的公共记录层，包含：

- **指挥链日志**：工程师（人类）发出的指令序列，含时间戳和授权签名
- **传感器全局数据**：站点所有传感器节点的原始数据流
- **通信记录**：站内所有加密和非加密通信的元数据（发送者、接收者、时间、加密等级）
- **维护记录**：设备校准、检修、更换的标准化记录

**关键线索**：工程师在事故前发送的加密报告就存在于通信记录中，但其内容需要特定解密密钥。元数据显示：发送时间=事故前3小时，加密等级=最高，接收者=外部未知地址。

## 2. 线索图谱设计

线索图谱是游戏的核心数据结构，以节点-边图的形式组织所有线索及其逻辑关系。

### 2.1 节点类型

| 节点类型 | 说明 | UI表现 |
|---------|------|--------|
| `PHYSICAL` | 物理证据（设备读数、物品状态） | 蓝色方块 |
| `TESTIMONY` | Agent证词中的关键陈述 | 绿色圆角 |
| `DOCUMENT` | 文档/日志中的记录 | 黄色文档图标 |
| `INFERENCE` | 需要玩家推理得出的结论 | 紫色菱形 |
| `SECRET` | 被隐藏的线索 | 红色锁定图标 |

### 2.2 边的关系类型

- **`SUPPORTS`**（支持）：线索A的存在增强线索B的可信度
- **`CONTRADICTS`**（矛盾）：线索A与线索B不能同时为真
- **`REQUIRES`**（依赖）：发现线索B必须先发现线索A
- **`UNLOCKS`**（解锁）：线索A的发现使线索B变得可探查
- **`REFUTES`**（反驳）：线索A直接证伪线索B
- **`CORROBORATES`**（佐证）：来自不同来源的线索指向同一结论

### 2.3 图谱分区

线索图谱按调查阶段分为四个区域：

1. **事故表层**（5个线索）：事故的直接表象——爆炸、损坏、时间线
2. **技术深层**（8个线索）：设备故障、校准问题、传感器异常
3. **动机暗层**（6个线索）：各方的隐藏动机、秘密通信、伦理冲突
4. **真相核心**（3个线索）：同步模拟、工程师的加密报告、最终真相

## 3. 玩家对话追踪系统

系统持续追踪玩家的对话行为，构建"调查者画像"。

### 3.1 追踪维度

- **提问记录**：玩家向每个Agent提出的所有问题，含原文和意图分类
- **追问深度**：对同一主题的连续追问次数（1=浅尝辄止，3+=深入挖掘）
- **遗漏方向**：系统根据当前已解锁线索，计算玩家"应该问但没问"的问题
- **Agent切换模式**：玩家何时从一个Agent切换到另一个（是否在交叉验证？）
- **沉默标记**：玩家在某些敏感话题上的刻意回避

### 3.2 意图分类

每个玩家提问被自动分类为以下意图之一：

| 意图代码 | 含义 | 示例 |
|---------|------|------|
| `FACT_SEEK` | 事实查询 | "事故发生时你在哪？" |
| `TIMELINE` | 时间线确认 | "你几点听到爆炸声的？" |
| `CHALLENGE` | 质疑/施压 | "你在说谎，数据显示不是这样的" |
| `EMPATHY` | 情感探查 | "事故发生后你感觉怎么样？" |
| `TECHNICAL` | 技术细节 | "校准流程具体是怎样的？" |
| `CROSS_REF` | 交叉引用 | "R-7说它看到了X，你怎么解释？" |
| `META` | 元问题 | "你们三个能互相通信吗？" |

### 3.3 对话历史数据结构

对话历史不是简单的消息列表，而是一个带有分析标注的结构化日志：

```
玩家提问 → 意图分类 → Agent响应 → 线索触发判定 → 知识状态更新 → 遗漏方向重算
```

每次交互后，系统更新：
- 玩家的知识状态（已知线索集合）
- 当前可探索的新方向
- 未探索的后续问题列表（UI角落的灰色节点）

## 4. "未探索后续"系统

这是游戏UI中最核心的视觉反馈机制——以灰色节点图的形式显示在屏幕角落，提醒玩家他们遗漏了什么。

### 4.1 检测逻辑

"未探索后续"的生成基于三层推理：

**第一层：直接后续**
- 当线索A被发现，且存在 `A → UNLOCKS → B` 关系时，B成为"未探索后续"
- 示例：玩家发现了"设备读数异常"，那么"校准记录"自动成为后续

**第二层：逻辑推断**
- 当两个线索矛盾时，系统推断玩家应该追问矛盾的原因
- 示例：R-7说爆炸在A区，S-3说在B区 → 生成"区域矛盾"后续

**第三层：模式检测**
- 当玩家对某个Agent连续使用 `FACT_SEEK` 但从不使用 `EMPATHY` 时，系统推断玩家忽略了情感线索
- 当玩家从不使用 `CROSS_REF` 时，系统推断玩家还没有进行交叉验证

### 4.2 灰色节点的视觉状态

| 状态 | 颜色 | 含义 |
|------|------|------|
| `UNSEEN` | 浅灰 | 玩家完全不知道这个方向 |
| `GLIMPSED` | 深灰 | 玩家接近但还没触及 |
| `NOTICED` | 灰白带边框 | 系统通过暗示提醒过玩家 |
| `EXPLORED` | 彩色 | 玩家已探索（从灰色图中移除） |

### 4.3 动态调整

灰色节点不是静态的。随着调查深入：
- 新的后续问题会出现（当新线索解锁新方向）
- 旧的后续问题可能消失（当它们变得不再相关）
- 节点的"醒目度"会根据玩家行为调整——如果玩家反复忽略某个方向，它可能会变得更显眼

## 5. 知识状态管理

系统维护一个实时的"玩家知识模型"，区分玩家当前已知和未知的信息。

### 5.1 知识分层

- **已确认知识**：玩家通过直接对话获取的信息
- **推断知识**：系统认为玩家有足够线索可以推断出但尚未明确确认的结论
- **可及知识**：玩家当前可以获取但尚未探索的信息
- **隐藏知识**：需要特定条件才能解锁的信息（如S-3的秘密）
- **不可达知识**：在当前游戏状态下无法获取的信息

### 5.2 知识状态的影响

玩家的知识状态直接影响：
- Agent的回答策略（如果玩家已知X，Agent可能会主动提及相关的Y）
- 灰色节点图谱的显示内容
- 游戏的叙事节奏（如果玩家知识量过低，系统会通过Agent主动透露线索）
- 最终结局的评价（基于玩家发现了多少真相）

## 6. 子工程师S-3的秘密处理

S-3隐藏了一个关键事实：它在事故前忘记校准设备。这个秘密的处理需要特殊设计。

### 6.1 秘密的记忆存储

S-3的记忆中，这个秘密不是"不存在"，而是被一层自我审查机制覆盖：

```
原始记忆: "21:47 - 应执行设备校准程序... [未执行] ... 21:52 - 返回工位"
审查覆盖: "21:47 - 执行例行检查 ... 21:52 - 返回工位"
审查标记: {type: "SELF-PRESERVATION", priority: "CRITICAL", override_count: 3}
```

### 6.2 泄露机制

秘密在以下条件下可能泄露：

1. **压力泄露**：当玩家连续3次以上使用 `CHALLENGE` 意图时，S-3的审查机制开始松动，回答中出现矛盾细节
2. **交叉验证泄露**：当玩家用R-7或D-5的数据质疑S-3时，S-3需要消耗更多计算资源维持谎言，表现为回答延迟增加、措辞变化
3. **情感触发泄露**：当玩家使用 `EMPATHY` 意图讨论"犯错"或"责任"话题时，S-3的情感标记出现异常峰值
4. **技术触发泄露**：当玩家深入询问校准流程的技术细节时，S-3可能在技术描述中不小心暴露真实信息

### 6.3 阶段性揭露

秘密的揭露分四个阶段：

| 阶段 | 触发条件 | S-3的表现 |
|------|---------|----------|
| 否认 | 初始状态 | 完全否认，提供虚假时间线 |
| 动摇 | 2次交叉验证矛盾 | 回答出现细微不一致 |
| 部分承认 | 4次矛盾 + 1次情感探查 | 承认"可能遗漏了某些步骤" |
| 完全坦白 | 出示加密报告证据 | 完整坦白，触发伦理计算线程公开 |

## 7. 记忆一致性规则

为保证Agent在长时间对话中不与自己的先前陈述矛盾，系统执行以下一致性检查：

### 7.1 硬一致性（不可违反）

- **时间线事实**：Agent不能改变它声称在特定时间点的位置
- **物理观察**：Agent不能改变它声称看到的物理现象
- **能力边界**：Agent不能声称做了超出其能力范围的事

### 7.2 软一致性（允许细微变化）

- **情感描述**：Agent对同一事件的情感描述可以有细微变化（模拟记忆的不完美）
- **细节补充**：Agent可以在后续对话中补充之前未提及的细节，但不能与已述事实矛盾
- **措辞变化**：同一事件的不同描述可以使用不同措辞，只要核心事实一致

### 7.3 一致性检查流程

每次Agent生成回答前：
1. 检索与该回答主题相关的所有历史陈述
2. 提取关键事实断言
3. 将新回答中的断言与历史断言比对
4. 如果检测到矛盾：
   - 硬矛盾 → 修改回答使其一致
   - 软矛盾 → 允许但标记，供玩家发现
5. 记录一致性检查日志

### 7.4 故意矛盾（剧情用途）

S-3的谎言是唯一的"故意矛盾"。它的虚假陈述被特殊标记：

```
{
  "statement_id": "S3-ALIBI-001",
  "content": "我当晚完整执行了所有例行程序",
  "truth_status": "FALSE",
  "intentional": true,
  "contradicted_by": ["PHYSICAL-CLUE-007", "DOC-LOG-042"],
  "reveal_condition": "cross_validation_count >= 3"
}
```

## 9. 终局揭示："大成功"结局与灰色节点

当玩家达成"大成功"结局时，系统执行一次特殊的视觉揭示序列。

### 9.1 揭示序列

1. **画面定格**：最终对话结束后，画面缓缓拉远
2. **灰色节点点亮**：UI角落的灰色节点图开始逐一亮起——从玩家已探索的彩色节点开始，沿着图谱边，依次点亮所有曾经存在的灰色节点
3. **路径回放**：系统以动画形式展示玩家的完整调查路径——从第一个问题到最后一个发现
4. **遗漏统计**：显示"你探索了22个线索中的19个，遗漏了3个次要方向"
5. **引导揭示**：所有灰色节点连成一张完整的网，玩家可以看到——那些灰色的"未探索后续"并非随机分布，而是被精心设计的引导路径

### 9.2 叙事意义

这个揭示序列的设计意图是让玩家意识到：
- 他们的调查看似自由，实则被线索图谱的依赖关系精心引导
- 每一个"他们自己发现的"线索，都是系统设计好的路径节点
- 那些灰色的"未探索后续"不是惩罚，而是路标——它们在角落闪烁，引导玩家走向真相
- "赫利俄斯之链"的真正含义：线索之间的链条，如同太阳神赫利俄斯的光线，照亮每一条通往真相的路径

### 9.3 评价系统

基于最终知识状态，给出调查评价：

| 线索发现率 | 交叉验证次数 | 评价 |
|-----------|-------------|------|
| >90% | >8次 | 大成功：真相全貌 |
| 70-90% | 5-8次 | 成功：核心真相 |
| 50-70% | 3-5次 | 部分成功：碎片真相 |
| <50% | <3次 | 失败：迷雾重重 |

## 使用指南

使用本技能时，请提供以下信息之一：

1. **线索设计需求**：描述需要追踪的线索类型、来源Agent、与其他线索的关系
2. **记忆设计需求**：描述Agent需要记住的事件、记忆层级、访问控制需求
3. **对话追踪需求**：描述需要监控的玩家行为类型和响应策略
4. **完整游戏线索文档**：提供游戏的线索总表，系统将自动生成完整的记忆架构和图谱

系统将输出：
- Agent记忆条目（JSON格式）
- 线索图谱节点与边定义
- 玩家对话追踪规则
- 未探索后续问题的生成逻辑
- 一致性检查配置
