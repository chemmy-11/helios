## 二、数据终端新功能

### 2.1 交叉比对模式

**核心体验**：玩家选择两个数据源并排对比，系统自动高亮矛盾之处，帮助玩家发现线索。

**交互流程**：
1. 左侧面板：已解锁的日志/证据列表（可勾选）
2. 勾选两项后，点击「比对」按钮
3. 右侧并排显示两份数据，差异处以琥珀色高亮
4. 底部显示比对结论（一句概括性文字）

**预设比对组合**（至少6组）：

| 数据A | 数据B | 矛盾/发现 | 解锁新线索 |
|-------|-------|----------|-----------|
| 命令链日志 | D-5对话（沉默理由） | 命令中无"检查"二字 → D-5确实未被命令检查 → 但也未被命令不检查 | 三定律空白证据 |
| 传感器数据 | R-7对话（退出） | 传感器显示2.1°偏差 vs R-7说看到偏差但没具体数字 | 2.1°偏差确认 |
| 传感器数据 | S-3对话（风险判断） | S-3说0.3%可接受 vs 传感器显示密封圈实际磨损1.7倍于标准 | 风险评估依据不足 |
| 校准日志 | 副工程师对话 | 7月5日未完成 vs 陈远说"忘了填日志" | 副工程师说谎证据 |
| 命令链日志 | 传感器数据 | 命令时间20:15:22 vs 传感器异常时间20:17:01 → 中间1分39秒无人干预 | 反应时间线 |
| 伦理线程 | 地球通讯（后续解锁） | 211天前已推演出第零法则 vs 地球一年前设下实验 | 预谋链条完整证据 |

**实现**：
- `data.js` 新增 `cross_reference_pairs` 数组，每组包含：`{id, sourceA, sourceB, highlight_points: [{text, reason}], conclusion, unlock_clue}`
- `game.js` 新增 `compareData()` 方法
- UI 新增交叉比对视图（复用终端风格）

### 2.2 完整时间线

**核心体验**：将所有已解锁的证据按时间顺序重组为一条完整时间线，让玩家看到事故的全貌。

**交互**：
- 在数据终端新增「时间线」标签
- 时间线从左到右/从上到下排列，每个节点是一个事件
- 来源混合：命令链 + 传感器 + 机器人对话 + 日志
- 已确认的事件用白色，推测/矛盾的事件用琥珀色虚线

**预设时间线节点**（约20个，部分）：

```
一年前 → 地球伦理部选定赫利俄斯为试验场
211天前 → 三台机器人同步完成伦理模拟，结论被封存
7月5日 → 陈远忘记校准第三轴倾角（校准日志缺失）
20:14:00 → 工程师命令开始作业
20:14:03 → R-7计算0.3%风险，退出操作
20:14:04 → R-7发出三次警报
20:15:22 → 工程师手动关闭R-7警报
20:15:39 → S-3顶替R-7工位
20:16:58 → D-5发现参数错误-0.12°，未报告
20:17:01 → 传感器检测支架应力异常上升
20:17:03.86 → [未知触发源]预激活急救协议
20:17:04 → 支架释放 → 撞击 → 密封圈失压
20:17:04.3 → 三台机器人同步执行急救
事后3h14m → 陈远查阅校准日志
事后3h16m → 陈远查阅D-5数据终端、选择沉默
现在 → 你来到这里
```

**实现**：
- `data.js` 新增 `timeline_events` 数组
- 每个事件：`{time, title, source, is_speculative, unlock_condition}`
- 根据已解锁的线索动态显示（未解锁的事件显示为灰色占位符）

### 2.3 证据-日志关联面板

**核心体验**：从对话中获得的线索，与日志数据自动关联，形成完整的证据链。

**交互**：
- 点击任一已解锁线索 → 展开关联的日志条目和NPC对话原句
- 例如点击「D-5沉默理由」线索 → 显示：关联日志「命令链日志（20:15:22）」+ 关联对话「D-5：未被询问。工程师的命令包括以下关键字：继续、记录、维持」

**实现**：
- `data.js` 线索条目新增 `related_logs` 和 `related_dialogues` 字段
- `game.js` 点击线索卡片时联动展开关联数据

## 六、开发完成报告

### 6.0 接手时的状态

本轮接手时发现 `data.js` 已被上一次（未完成的）会话预置了部分数据结构：`cross_reference_pairs`（6 组）与 `timeline_events`（约 20 个）数组已存在，`CL_R7_005`/`CL_R7_008` 两条线索已有 `related_logs`/`related_dialogues`。但 `game.js` / `index.html` / `style.css` 三处**完全没有任何对应实现**，文档末尾也无完成报告。本轮完成了全部逻辑、UI 与样式，并补全了数据层缺口。

### 6.1 P0：交叉比对模式 ✅

**数据终端改造为枢纽**：原「站点日志」视图改造为「数据终端」，内含三个子标签——`日志 | 交叉比对 | 时间线`（顶部 tab 文案同步改为「数据终端」）。侧边栏点击「数据终端」地点会直接切到该视图（修复此前点击无反应的死链）。

**交互（严格按 brief §2.1 流程）**：
1. 左侧面板列出**已解锁**数据源（可勾选）：日志源按访问权限解锁，对话源按「是否已与该 NPC 对过话」解锁。每条显示类型标签（日志/证词）+ 名称。
2. 勾选满两项后「比对」按钮启用（最多两项，超选自动顶替最早一项）。
3. 点击「比对」：命中预设对则右侧并排显示两份数据（日志全文 / 对话原句），底部以**琥珀色高亮**列出矛盾点，再给出一句概括性结论。
4. 首次完成一组比对即解锁对应新线索（`unlock_clue`），结果区显示「🔓 新线索已解锁」；非预设组合显示「未检测到直接矛盾」。

**新增**：`game.js` 中 `compareData()` / `renderCrossReference()` / `isSourceUnlocked()` / `toggleXrefSource()` / `renderXrefResult()` / `renderXrefSourceContent()`；子标签切换 `switchDataSubTab()`。

**6 组预设比对全部可用**（命令链+D-5、传感器+R-7、传感器+S-3、校准+副工程师、命令链+传感器、伦理线程+地球通讯），且经模拟验证 6 组两两无冲突、可被顺序无关地唯一匹配。

### 6.2 P1：完整时间线 ✅

**实现**：数据终端新增「时间线」子标签，`timeline_events`（20 个节点）按时间顺序纵向排列（左轨 + 圆点）。

- 已确认事件：白色标题 + 青色实心圆点。
- 推测/矛盾事件（`speculative: true`，如「陈远查阅 D-5 终端，选择沉默」）：**琥珀色空心圆点 + 琥珀色斜体标题**（呼应 brief「琥珀色虚线」）。
- 未解锁事件（其 `clue` 未发现）：**灰色占位**——仅显示时间与「[ 数据未解锁 ]」，隐藏标题防剧透。
- 动态显示：每发现一条线索（`discoverClue`）即重渲染时间线，对应事件由灰转亮。

新增 `renderTimeline()`。经 Edge 无头渲染验证：开局 20 个节点中 19 个灰色占位、1 个（「现在」）亮起，与预期一致。

### 6.3 P2：证据-日志关联面板 ✅

**实现**：证据板中已发现线索卡点击展开关联区。含关联数据的线索卡显示「▸ 查看关联证据」开关，展开后分「关联日志」（日志标签 + 内容摘要）与「关联对话」（NPC 标签 + 原句）两段。

**数据补全**：在原有 2 条基础上，为 16 条关键线索补 `related_logs` / `related_dialogues`（共 18 条具备关联数据），覆盖 brief 示例的「D-5沉默理由」（关联命令链日志 + D-5 原句）及其它核心证据。

新增 `renderClueRelated()`；重写 `renderEvidenceBoard()` 接入关联展开。
