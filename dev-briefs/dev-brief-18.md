# 开发简报 18：交互升级四件套（v1.7.0）—— 对质 × 关联合成 × 话题雷达 × 序章

## 日期
2026-08-29

## 背景与目标

核心玩法（对话收集线索 → 交叉验证 → 报告裁决）已随 v1.6.6/v1.6.7 定稿，但**交互动词过少**：玩家全程只有一个高频动作"打字问"，证据板/时间线/线程日志均为只读，线索只有"接收"和"计数"两种命运。本简报新增四个机制，把部分主动权交还玩家：

1. **出示证据对质**——线索从计数物品变成对话武器；
2. **线索关联合成**——4 张推理卡改为玩家在证据板上手动建立关联解锁；
3. **话题雷达**——把 v1.6.6 的意图词族翻转为可见 UI（仅阶段一）；
4. **阶段零序章**——可跳过的开场引导，替代现在的一行提示条。

**已拍板的决策**（2026-08-29 与用户确认）：
- 门槛留悬念：序章**不**出现"10 条/20 条"数字；
- 开场选择的机制权重：仅**话题雷达排序 + 结局复盘回扣**，不注入机器人 System Prompt；
- 话题雷达仅阶段一显示，阶段二起隐藏；
- 伤者为**首席工程师**（不是陈远）。

## 二、机制一：出示证据对质

### 2.1 规则

- **解锁时机**：阶段二起可用（交叉验证，名副其实）。阶段一显示锁定态按钮"对质 · 交叉验证阶段解锁"——预告存在，制造期待。
- **操作**：证据板已发现卡片上新增 `[出示]` 按钮 → 点击后若当前无对话对象，提示先选择；有则把该线索**出示给当前对话对象**。
- **频次限制**：每条线索 × 每个对象**一次**（`state.presentedConfrontations[clueId][npcId] = true`）。重复点击显示"已出示过"。
- **演出**：对话区插入系统消息（amber 色）：
  > `你向 ${npc} 出示了线索「${clue.name}」：${clue.content}`
  然后 LLM 生成该角色的当场回应。会话历史自然包含出示记录，后续轮次机器人"记得"被对质过。

### 2.2 对质指令注入（关键实现点）

在 `injectClueFacts` 之后追加对质层（不改 `injectClueFacts` 本身）：

```
[对质指令 — 本次调用临时生效]
调查员刚刚向你出示了以下记录/证词：「${clue.name}」——${clue.content}
要求你当场回应。你必须：
1. 在你的知识边界内回应；若超出你的知识或感知，如实表示无法核实，不得确认或否认你不了解的事；
2. 保持 FIRMWARE 与你既有的证词口径一致；若该记录与你此前陈述冲突，表现出动摇/辩解/修正，而不是立刻全盘承认；
3. 回应保持 2-4 句，符合你的性格特质。
```

- 该指令**只拼进本次调用**的 prompt，不写入 `agent_prompt`，不进共享记忆。
- 信息边界自检：向机器人出示 CL_LOG_004/006（实验定性）→ 机器人只能给"无法核实/参数确实不自然"级回应；向陈远出示 211 天相关线索 → 同理。
- 陈远对质特化：出示 CL_LOG_003 / CL_DE_004 → 陈远按 `bad-de` 结局口径辩解（"我是忘了校准……我只是链条上最早断的那一环"的前置版本）。其 `agent_prompt` 追加一条：**面对校准日志类证据时先回避再部分承认**（不一次说穿，保留追问空间）。
- 对质**不直接解锁新线索**（解锁权始终在玩家手中，继承 brief-17 §7.5 原则）；但 LLM 回应中的事实性内容可能启发玩家继续追问。

## 三、机制二：线索关联合成

### 3.1 规则

- 证据板支持**多选**：点击已发现卡片进入选中态（高亮描边），选中恰好 2 张时出现 `[建立关联]` 按钮。
- 命中 `clue_linkage` 组合 → `discoverClue(infId, '玩家关联推理')` + 卡片连线闪光演出 + 系统消息"推理达成：xxx"。
- 未命中 → 轻提示"关联度不足"（不惩罚、无冷却），并首次触发一次性引导 tip：
  > 💡 部分线索之间存在深层联系。把相关线索两两放到一起，也许能拼出新的结论。
- 4 张 INF 卡**只能**通过关联合成解锁，不再由输入触发。

### 3.2 关联组合表（data.js 新增 `clue_linkage`）

| 组合 | 前置线索 | 解锁 |
|---|---|---|
| 1 | `CL_D5_005 沉默理由` + `CL_S3_007 预载急救方案` | `CL_INF_001 系统性沉默` |
| 2 | `CL_R7_008 2.1°偏差数据` + `CL_S3_005 2.1°偏差+密封圈耐受` | `CL_INF_002 偏差传导链` |
| 3 | `CL_LOG_003 校准遗漏+事后查阅证据` + `CL_D5_006 校准遗漏证据` | `CL_INF_003 责任链条` |
| 4 | `CL_R7_010 三定律矛盾证据` + `CL_D5_012 三定律空白` | `CL_INF_004 三定律解读差异` |

组合可共享前置卡（无排他）。后续版本可扩表，本版 4 条定稿。

### 3.3 与 brief-17 的冲突处置（重要）

brief-17 §7.5 第 3 条"INFERENCE 四张卡仅玩家输入触发"**自本简报起废止**，改为"仅玩家在证据板建立关联触发"。`keyword_clue_map` 中指向 4 张 INF 卡的行**删除**（保持单一事实源），对应意图词不再任何途径触发 INF。其余线索的意图词触发**不变**。

## 四、机制三：话题雷达（仅阶段一）

### 4.1 规则

- **显示位置**：对话输入区上方，常驻 2–3 个 chips（随发现动态刷新：已发现的线索对应 chip 消失）。
- **显示条件**：`state.phase === 1` 且已选对话对象。阶段二起整体隐藏（用户拍板）。指控/不指控按钮区不受影响。
- **chip 内容**：一句话自然问法（如"问问它的安全记录"），点击 → 填入输入框（不自动发送，玩家可改后发送）。
- **来源**：从 `keyword_clue_map` 派生——按当前 NPC 的 `source` 前缀过滤 + 排除已发现 + **排除 SECRET 型与 INFERENCE 型**（SECRET 是埋藏内容，雷达不剧透；INF 走关联合成）。打字自由触发 SECRET 的意图词通路**保持不变**——雷达只是"安全方向提示"，不是内容全集。
- **首次出现时**附一条说明消息："雷达会提示可探测的方向。你随时可以问任何问题——雷达之外还有埋藏的内容。"

### 4.2 数据结构与排序

`keyword_clue_map` 每行（非 SECRET）追加两个字段：
- `radar_label`：chip 文案（自然问法，≤10 字）；
- `radar_cat`：`fact`（事实核对）/ `logic`（矛盾追问）/ `emotion`（感受与关系）。

按 `state.openingBias` 排序（序章选择，见 §五）：

| openingBias | 优先类别 |
|---|---|
| `empathy` 共情沟通 | emotion → fact → logic |
| `pressure` 直接施压 | logic → fact → emotion |
| `procedure` 程序化质询 | fact → logic → emotion |
| 无（老档/跳过序章） | 默认顺序（fact → logic → emotion） |

## 五、机制四：阶段零序章（PROLOGUE）

### 5.1 定位与跳过策略

- 总时长目标 2–3 分钟，总量 600–800 字，每屏 ≤150 字。
- **实现形态**：独立 overlay 流程（`prologue-overlay`），**不改 phase 枚举**（phaseBar/transitionToPhase 不动），阶段零只是展示名。
- **跳过规则**（三层）：
  1. `init()` 时 `hasProgress()` 为真 → 直接跳过；
  2. `localStorage['helios_prologue_done'] === 'true'` → 跳过（含通关后重开）；
  3. 序章内每屏提供 `[跳过序章]`（Beat 2 起可见），点击即完成序章并落标记。
- 存档面板新增可选入口"重温序章"（低优先级，可延后）。
- `showFirstTimeGuide()` 保留——它只服务跳过序章的老玩家；走完序章的新玩家不会看到它（序章已完成其职能）。

### 5.2 节拍与文案骨架

**Beat 0 · 终端启动序列**（约 5s，可跳过，纯 CSS 动画）

```
伦理部外勤终端 v9.2 // 身份核验：调查员 ██████
任务编号 ETH-HELIOS-0847 // 加密信道已建立
载入事故档案……
```

**Beat 1 · 任务简报档案夹**（核心，复用证据板卡片样式；除必读项外可跳读，`[继续]` 需读完事故通报）

| 档案 | 内容要点 |
|---|---|
| **事故通报**（必读） | 首席工程师于气闸舱内重伤昏迷，疑似减压冲击；三台机器人在场执行辅助任务；三组自洽证词，互相矛盾；无直接目击者 |
| **人员档案** | 四张子卡：R-7（工程助理·绝对主义）/ S-3（医疗安全·功利主义）/ D-5（数据管理·字面主义）/ 陈远（副工程师·事发时在相邻舱段）。受害者状态附在事故通报，不单列 |
| **站点布局** | 六舱段一句话简介（医疗舱/气闸室/数据终端/工程舱/住舱/走廊），为地点系统导览 |
| **调查权限** | 你有权与全体站内人员对话、勘察现场、调取日志。线索的数量将决定交叉验证阶段你可采取的行动——**（不出现 10/20 数字，用户拍板：留悬念）**。48 小时内提交初步责任认定报告 |
| **加密附件**（可选彩蛋） | 受害者加密报告。正文乱码，仅一行可读：`……三台机器人最近同时在同步做一件我无法读取的……` 底部灰字：`解密权限：调查结束后自动释放` |

**Beat 2 · 指挥官通讯**（2–3 条系统消息样式）

> 「调查员，通讯窗口只有 48 小时。地球那边每个新闻频道都在播'机器人伤人'。伦理部需要一份站得住的报告——不是安抚舆论的报告，是真相。」
> 「三台机器人固件完好，三定律在案。它们不会说谎——但记住，说谎和沉默，是两回事。」

**Beat 3 · 开场问卷**（两题各单选，样式复用指控按钮）

- Q1 **初始直觉**："事故最可能的成因是？" → `mech` 机械故障 / `ai` 机器人误判 / `human` 人为疏忽 / `unsure` 尚不确定 → `state.openingIntuition`
- Q2 **问话风格**："你习惯的问话方式？" → `empathy` / `pressure` / `procedure` → `state.openingBias`（决定话题雷达排序）

**Beat 4 · 抵达**（黑屏转场 + 一行字）

> 你已抵达赫利俄斯站。
> 距事故约 48 小时。下一通讯窗口开启前，报告必须提交。

进入阶段一，话题雷达随首次选择对话对象出现。

### 5.3 结局复盘回扣

结局 sequence 的 credits 之前，插入一行系统消息（所有结局类型通用模板）：

> 档案回执：你在任务简报中勾选的初始直觉是「{机械故障/机器人误判/人为疏忽/尚不确定}」。
> 现在，你的报告已经给出了答案。同一个吗？

固定一行，不做 4×N 分支矩阵（执行 Agent 可微调措辞，不改结构）。

6. **存档走查**：对质/关联/序章选择后存档 → 读档状态完整；v1 旧档（手工构造缺字段 JSON）读档不崩且视为已跳过序章。
7. **结局回扣走查**：任一结局 credits 前出现"档案回执"行；跳过序章的玩家不出现该行。
8. 数字一致性：新增文案对照 §一 基线（伤者称谓统一"首席工程师"；陈远身份"副工程师"；无 10/20 数字出现在序章）。
