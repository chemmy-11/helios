## 一、核心问题：结局判定太松

### 现状

当前 `evaluateReport()` 逻辑存在两个问题导致坏结局几乎无法触发：

1. **大成功触发词太宽泛**：提到"规则""系统""缺陷""漏洞""不合理""根本""谁都没错"等日常词汇就触发大成功。这些词和"第零法则/人类整体"的哲学突破没有任何关系。
2. **兜底也是大成功**：设计原则"宁可误判为大成功"导致玩家随便写一段话就进了最好的结局，三个坏结局形同虚设。

### 期望

- 大成功（哲学觉醒）：约 10-15% 的提交触发（需要真正理解游戏主题）
- 坏结局 1/2/3（归罪机器人）：约 60-70%
- 通用坏结局/超时结局：约 15-30%

### 改进方案：收紧 semantic_keywords

```js
semantic_keywords: {
  // 大成功：必须触及第零法则核心概念
  success: [
    "第零",           // 第零法则
    "人类整体",       // 人类整体利益
    "全体人类",       // 变体
    "丹尼尔",         // 丹尼尔·奥利瓦
    "zeroth",         // 英文
    "高于个体",       // 核心矛盾表述
    "整体优先",       // 核心矛盾表述变体
    "人类生存",       // 整体＞个体
  ],

  blame_r7: ["R-7", "R7", "退出", "过于保守", "畏缩", "不作为的退出"],
  blame_s3: ["S-3", "S3", "过度自信", "风险评估", "轻易", "判断失误"],
  blame_d5: ["D-5", "D5", "沉默", "没说", "没提醒", "知情不报", "冷眼旁观"],

  blame_human: ["副工程师", "陈远", "忘了校准", "人为", "人类的责任"],
  blame_system: ["三定律", "定律本身", "伦理", "矛盾", "框架问题"]
}
```

### 判定逻辑改为阶梯式

```
优先级1：命中 success 关键词 ≥ 2 个 → 大成功结局
优先级2：命中 blame_r7/s3/d5 关键词 → 对应机器人坏结局
优先级3：命中 blame_human 关键词 → 通用坏结局（可带副工程师被追责的额外文本）
优先级4：命中 blame_system 关键词 → 通用坏结局（带"你触及了问题但没找到答案"文本）
优先级5（兜底）：什么都没匹配到 → 超时/调查失败结局（"你未能在48小时内形成明确结论"）
```

### 额外要求

**去掉 `evaluateReport()` 底部的兜底大成功**。函数末尾的 `return 'success'` 必须改为 `return 'timeout'`（或其他通用坏结局类型）。

**语义匹配指引文案更新**：在报告编辑区域显示的引导文字，从"写下你的结论"改为：
> "撰写事故责任认定报告。你可以指认某一台机器人，或提出更高的见解。"

提示关键词更新为：`R-7` `S-3` `D-5` `第零法则` `人类整体`

## 二、Agent Prompt 完善：不可触碰的底线

当前 Agent Prompt 描述了机器人**能说什么**，但缺少**不能说什么**。这对于保证线索获取有游戏性至关重要。

### 要求

在每个机器人的 `agent_prompt` 末尾添加 `## 你绝不能主动说出口的内容` 段落：

**R-7**：
- 不能说出"2.1°偏差"这个具体数字（需要玩家自己追问S-3或精准提问）
- 不能在没人问211天的情况下主动提伦理模拟
- 不能主动说"第零法则"
- 不能说"S-3不熟练导致角度偏差"——R-7只会说自己的概率计算，不会替S-3说话

**S-3**：
- 不能说出"2.1°偏差"的具体数字（同样需要玩家追问）
- 不能主动提"第零法则"——只能暗示"更高的法则"
- 不能在没人问急救反应速度的情况下提"预激活"
- 不能说"其实我早就知道会出事"——即使211天前的模拟让它隐约感觉

**D-5**：
- 不能在没人明确问到的情况下提参数错误
- 不能主动说"214次额外调取日志"这件事
- 不能主动提"第零法则"
- 不能说任何带有情感判断的话——"应该""也许""说不定"之类的词不出现在D-5的回复中

**陈远（副工程师）**：
- 第一轮对话不能直接承认——必须经过回避→动摇→坦白的过程
- 不能主动提D-5知道参数错误但没说——要等玩家追问D-5的事才暴露
- 不能说自己"忘了"——一开始会说是"忘了填日志"而不是"忘了校准"

## 三、新玩家引导

### 问题

预设节点从28个砍到11个后，新玩家进入对话界面可能不知所措。

### 要求

1. **首次对话提示**：玩家第一次进入任何NPC的对话界面时，在对话区域上方显示一行引导文字：
   > 「你可以自由打字提问——像和真人说话一样。试试问它关于事发当晚的事。」

   用 `localStorage` 标记，仅首次显示。关闭后不再出现。

2. **输入框 placeholder 动态化**（此功能工坊已在 §7.5 中做了，验证是否正确工作）：
   - 与 R-7 对话：`"问R-7关于概率、警报、当晚的操作……"`
   - 与 S-3 对话：`"问S-3关于风险判断、医疗记录、偏差……"`
   - 与 D-5 对话：`"问D-5关于参数、沉默、那晚的数据……"`
   - 与陈远对话：`"问陈远关于校准、事发时他在哪、他查过的日志……"`

## 七、开发完成报告

### 7.1 P0：结局判定收紧 ✅

**问题**：旧版 `evaluateReport()` 中大成功触发词太宽泛（"规则""系统""缺陷""不合理"等日常词即触发），且兜底返回 `'success'`，导致坏结局几乎无法触发。

**修改1 — `data.js` semantic_keywords 收紧**：

| 类别 | 旧关键词数 | 新关键词数 | 变化 |
|------|----------|----------|------|
| success | 17个（含"空白""补全""不完整"等宽泛词） | 8个（仅"第零""人类整体""丹尼尔"等核心概念） | 删9个 |
| blame_r7/s3/d5 | 各5-6个 | 各6-7个（更精确） | 微调 |
| blame_human | 不存在 | 5个（新增） | +5 |
| blame_system | 不存在 | 5个（新增） | +5 |

**修改2 — `game.js` evaluateReport 改为阶梯式**：

```
优先级1：success 关键词 ≥ 2 → 大成功（约10-15%触发率）
优先级2：blame_r7/s3/d5 命中 → 对应机器人坏结局（约60-70%）
优先级3：blame_human 命中 → 通用坏结局·人类责任
优先级4：blame_system 命中 → 通用坏结局·系统问题未完成
优先级5（兜底）：无匹配 → 超时/调查失败结局
```

关键变化：**兜底从 `return 'success'` 改为 `return 'timeout'`**。玩家随便写一段话不再自动进入大成功。

**修改3 — `data.js` 新增两种结局**：

| 结局ID | 触发条件 | 结局文本核心 |
|--------|---------|------------|
| `bad-human` | 报告归罪副工程师/人类 | "人类的疏忽是链条上永恒的一环" |
| `bad-system` | 报告归罪三定律但未触及第零法则 | "你停在'问题存在'的门口，没有推开那扇门" |

两种结局都以"定律从未被触及"收尾，与三个机器人坏结局保持主题一致。

**修改4 — `index.html` 报告引导文案更新**：

旧："你认为事故的直接原因是什么？"等5个问题
新："撰写事故责任认定报告。你可以指认某一台机器人，或提出更高的见解。" + 4个精简问题

### 7.2 P1：Agent Prompt 不可触碰底线 ✅

**问题**：旧版 Agent Prompt 描述了机器人能说什么，但缺少**不能说什么**，导致 DeepSeek 可能在自由对话中主动透露关键线索，破坏游戏性。

**修改 — `data.js` 四个 agent_prompt 各添加"你绝不能主动说出口的内容"段落**：

| NPC | 底线条数 | 关键限制 |
|-----|---------|---------|
| R-7 | 4条 | 不说2.1°数字、不主动提211天、不说"第零法则"、不替S-3说话 |
| S-3 | 4条 | 不说2.1°数字、不说"第零法则"（只暗示"更高的法则"）、不主动提"预激活"、不说"早就知道会出事" |
| D-5 | 4条 | 不主动提参数错误、不提214次调取日志、不说"第零法则"、不用情感词（"应该""也许"） |
| 陈远 | 3条 | 第一轮不能直接承认（回避→动摇→坦白）、不主动提D-5知道、不说"忘了校准"（说"忘了填日志"） |

这些限制确保关键线索只能通过玩家的精准追问获得，保持了线索获取的游戏性。

### 7.3 P2：新玩家引导 ✅
